# 测试与实验产物规范

> **目录边界：** 项目真实运行数据使用 `data/`；测试与实验不得向该目录写入样本、临时文件、验证结果或分析日志。

---

## 存储位置

| 内容 | 位置 |
| --- | --- |
| 可重复使用的测试样本 | `tests/fixtures/`，记录来源和用途。 |
| 测试临时文件、模拟资源及本地数据库文件 | `tests/tmp/<独立临时目录>/`。 |
| 实验原始数据与运行结果 | `experiment/<主题>/<运行标识>/`。 |
| 实验人工分析 | 对应实验目录中的 `analysis.md`。 |

历史验证产物保持内容不变迁入 `experiment/`，不要求为迁移重命名原始运行标识。目录移动后检查文档及产物之间的相对链接。

---

## 测试隔离与清理

测试统一使用 `tests.support.temporary_directory()` 创建临时目录，结束后清理其内容。`tests/`、`experiment/` 和 `scripts/` 整体不纳入 Git，固定样本、测试代码及实验工具均仅在本地保留；新克隆需另行取得所需工具和样本。只有项目描述与规范文档随仓库交付，具体允许清单见[版本管理范围](../capability/application/runtime.md#版本管理范围)。

创建应用、文件存储和持久化服务时显式设置测试 `resource_root`，不能因关闭后台服务而继续使用真实 `data/` 默认路径。配置测试可以断言生产默认路径，但不得在该路径上产生副作用。

测试或实验不得把生成的样本插入正式业务数据；联调使用隔离数据库、消息流或可明确辨识且可清理的临时资源，结束后清理自己创建的记录与文件，不删除业务数据。

---

## 实验原始产物与分析

每次新实验使用独立运行标识，保存原始响应、结果、指标和必要的 manifest；不覆盖既有实验。产物不包含接口密钥、数据库密码或认证头，目录不得被打包进应用镜像。

分析请求的完整记录追加到该次运行的 `analysis.md`，以带时区时间作为二级标题，记录分析范围、结论摘要、关键证据、原因判断、建议措施和验证状态。相邻章节使用 `---` 分隔；已有原始产物保持不变，只追加分析记录，不将推断写回原始结果。

项目开发要求见 [AGENTS.md](../../AGENTS.md)，实验入口见 experiment/readme.md（本地 `experiment/readme.md`）。
