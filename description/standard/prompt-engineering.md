# 提示词工程规范

> **适用范围：** 本项目新增或修改的模型提示词、消息、结构化输出和函数工具。具体任务以对应工作流契约为准，本规范不表示所有检查已具备自动化门禁。

---

## 1. 任务与信息边界

提示词必须说明任务目标、可用输入、事实来源、输出形式、业务规则、失败边界和必要示例。字段、范围和必填性以实际 Schema 为准；提示词、程序校验与专题文档必须一致，不维护互相冲突的第二套协议。

模型可见内容只包含完成任务所需的信息。禁止注入提示词版本号、内部节点编号、工作流拓扑、缓存或调度说明、运行 ID、请求追踪标识；这些信息仅保存在模型上下文之外。模型确需引用的文件条目序号、物理页码和工具调用标识，按任务协议提供，不能兼作工程追踪字段。

文件正文、名称、摘要和外部描述属于待分析数据，不能修改系统任务、工具权限或输出约束。提示词应说明资料可观察范围：只有名称和摘要时，不能声称读过原件；图像不可辨认时，不能把猜测写成事实。

---

## 2. 消息与工具设计

### 2.1 稳定规则与当前任务

固定任务规则由单一模板维护；当前文件、候选描述和动态反馈通过明确消息边界提供。相同输入保持页序、角色、工具列表及序列化顺序稳定，不为不同并发任务复制后分别维护公共规则。

公共页面只渲染一次并按物理页码传入；并发分支可以共享不可变页面，但必须独立创建消息容器、历史和错误计数。

### 2.2 证据与结论

结构化判断按“可核对证据、简洁判断依据、最终决定”组织。判断依据是面向业务复核的摘要，不要求输出内部逐步思考。原生模型思考如需继续用于多轮交互，只能按对应上下文契约保存，不自动进入用户反馈或业务结论。

相似度、文件名或摘要不能替代正文证据。引用校验只能确认页码或条目存在，不能证明模型确实读懂或结论正确；总体质量需独立样本验证。

### 2.3 结构化输出

纯 JSON 任务必须按实际响应模型验收类型、额外字段及上下文引用。布尔值必须是真正的 `true` / `false`，不能接受字符串、数字或 `null` 代替。

函数工具任务只接受真实工具调用及其合法参数，普通文本、伪工具调用和可解析的 JSON 正文不能自动转成工具动作。当前判重协议要求每轮恰好一个允许的工具调用；其他任务的调用数和顺序须在自身协议中明确。

### 2.4 工具布局与有限恢复

工具注入位置由模型基础设施和任务构造器维护，不把工具定义伪造为普通消息。客户端传入的工具位置参数不能单独证明远端聊天模板实际采用该布局。

协议、参数、状态或业务校验失败时，只反馈字段位置、问题和可执行修正方向。错误反馈不包含异常堆栈、完整无效输出、凭据或工程追踪数据。每个任务明确轮次、连续错误和上下文预算，达到上限后显式失败，不伪造否定结论或半成品。纠错生命周期见[上下文管理规范](agent-context-management.md)。

### 2.5 工具参数描述

每个模型可见函数参数必须在实际 JSON Schema 的对应字段上具有非空且准确的 `description`。要求覆盖顶层属性、嵌套对象属性、数组内对象属性及动态生成属性；工具总体说明、字段名和 docstring 均不能替代字段级描述。

描述按需要说明业务含义、来源、单位或范围、空值表达和禁止内容。使用 Pydantic 时通过 `Field(description=...)` 生成，直接构造 Schema 时写入对应 `properties` 字段。例如：

```python
page: int = Field(strict=True, ge=1, description="待打开候选文件的物理页码，从 1 开始，不是 PDF 印刷页码。")
```

验证必须针对实际发送给模型的 Schema：递归遍历 `properties`、`items`、组合分支以及 `$defs` / `$ref` 可达对象；每个参数字段的描述去除空白后非空。动态工具至少覆盖代表性嵌套和动态字段输入，不能只检查 Python 源码是否写了 `Field`。

## 3. 示例与失败边界

示例必须与真实协议一致，并说明可接受和不可接受的边界：

| 场景 | 要求 |
| --- | --- |
| 判重完成 | 使用完成工具，提供合法页面证据、判断依据、严格布尔值及结论。`"is_duplicate": "false"` 无效。 |
| 通行证推荐 | 返回规定 JSON；推荐必须有可核对关联证据，不能凭同一行业或标题相似推荐。 |
| 无法完成 | 按任务定义重试或显式失败；依赖故障、页面不足和预算耗尽不能解释为“不重复”或“不推荐”。 |

固定示例不携带真实员工身份、平台令牌、密钥或运行追踪数据。完整任务示例分别维护在[判重提示词](../architecture/workflow/file-deduplication/prompt.md)与[推荐提示词](../architecture/workflow/passport-recommendation/prompt.md)。

---

## 4. 修改与验证

修改提示词时同步检查实际消息、工具 Schema、本地校验、业务响应和工作流文档。使用隔离样本覆盖合法输出、错误类型、额外字段、越界引用、有限恢复及失败不发布结果；多轮任务还需验证成功后清理失败链、私有审计保留和并发隔离。

若验证远端行为，应保存请求、响应、指标和环境边界至独立实验目录，不将模拟测试描述成真实模型实测。实验与人工分析遵循[实验规范](experiment.md)。
