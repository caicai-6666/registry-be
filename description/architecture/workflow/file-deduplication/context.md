# 判重 Agent 上下文与页面窗口

> **当前阶段：** 已实现多轮运行、友好页面折叠、有限纠错与终态校验。输入输出见[子图入口](readme.md)，模型工具参数见[工具契约](tool.md)，固定任务规则见[系统提示词](prompt.md)。
>
> **约定：** A 为当前申请文件，B 为本分支绑定的一份相似文件。A 全文常驻，B 按需打开；B 目前仍由主图完整渲染到私有内存，按窗口发送图像，并非按需渲染。

---

## 首轮顺序与工具位置

| 顺序 | 内容 | 消息或注入方式 | 生命周期 |
| --- | --- | --- | --- |
| 1 | 固定系统任务、证据及工具规则 | `system` | 固定前缀。 |
| 2 | A 全部物理页面，标签和图像交替 | `user` | 同一申请内固定。 |
| 3 | A 名称、摘要及总页数 | 独立 `user` | 同一申请内固定。 |
| 4 | 两个工具定义 | 服务端聊天模板 | 同一配置下固定。 |
| 5 | B 名称、摘要、申请人、审核人及总页数 | 独立 `user` | 当前分支固定。 |
| 6 | 已接受动作的原生思考、含页面的 tool 回执及临时纠错 | 动态后缀 | 每轮重建。 |

`build_initial_messages(pair)` 返回固定消息列表和 B 任务锚点。当前锚点为零基下标 `3`，由构建函数按实际消息数量生成；运行器每轮传入 `tool_placement="before_task"`、`tool_task_index=3` 和 `tool_choice="auto"`。初始三条 user 消息只在前缀出现，后续只追加 assistant/tool，不追加 user；工具位置固定，不把工具定义伪造为普通文本。

首轮只有固定 system 与三条 user，B 没有视觉页面，也没有额外状态消息。模型先通过 `read_candidate_pages` 打开页面；图像作为该次 tool 回执的多模态 content 返回，后续依靠原生思考及工具对话继续比较。B 的人员来自正式资源表，缺失时保留 `null`；只作为元数据线索，不能证明重复或改变工具权限。模型可见内容仅描述文件 A/B，不暴露申请处理、召回或审核编排。

客户端已校验并传递锚点。服务端自定义聊天模板仍必须支持这两个参数；模拟请求体测试不能证明远端实际工具位置。

## 文件 A 页面组装

`build_file_a_pages_message(pdf)` 接收完整 `PreparedPDF`，返回独立 user 消息，按页码固定排列：

```text
【文件A -- 页面1】
<第 1 页图像>
【文件A -- 页面2】
<第 2 页图像>
……
```

缺页、重复页、乱序及空图像直接拒绝，不通过排序掩盖异常。组装不读磁盘、不重新渲染、不进行 Base64 编码，复用 `pdf_page_content()` 的不可变 PNG 引用和稳定 UUID；每次生成独立消息容器。

## 文件 B 友好折叠

对话循环用局部页码列表记录最近访问顺序，最多保留 n 个不同 B 图像。打开或重新打开的页移到最近访问列表末尾，超出上限时折叠最早未再次访问的页面。同页重复打开不占多个槽，单次请求数量也不能超过 n。

旧页在原 tool 回执中保留可读的折叠卡片、物理页码及已经接受的观察，不直接删除阅读轨迹。例如 n=2，打开 1、2、3 页后：

```text
【文件B -- 页面1（已折叠，可重新打开）】
<之前接受的精简观察；没有观察则明确提示重新打开>
【文件B -- 页面2】
<第 2 页图像>
【文件B -- 页面3】
<第 3 页图像>
```

折叠卡片不携带完整图像。任一请求最多包含 `A.page_count + n` 个图像块；`fold_file_b_pages()` 处理整段工具历史，只有当前窗口的最近一次展示携带图像；折叠的回执保留卡片，同页重开会折叠旧展示，避免历史重复图片突破上限。重新打开时取同一个内存页面和 UUID，底层客户端根据服务端缓存情况决定发送完整图片还是 UUID 引用。卡片不是原图或充分检查的证明，需要核对数字、正文或细节时应重开。

## 对话轨迹与读页校验

没有独立工作区对象、管理工具或状态消息。正常轨迹为：

```text
system + user(A页面) + user(A信息) + user(B信息)
assistant（原生思考 + 读页调用1）
tool（读页1返回的页面图像）
assistant（原生思考 + 读页调用2）
tool（读页2返回的页面图像）
……
assistant（原生思考 + finish_comparison）
```

旧 tool 图像在原位置友好折叠，assistant 的合法原生思考持续保留。程序仅保留页码列表 `visible_pages`、已实际展示页集合 `presented_pages`、已接受观察及读页计数，这些局部信息用于图像上限、折叠说明和证据引用校验，不作为通用工作区发送给模型。

读页先校验参数、页码及当前可见引用，再构建候选工具历史，检查观察条目和上下文预算；全部通过后才接受历史、页码、观察及计数。失败保留原历史和图像，不提交观察。只有请求成功送达并收到响应后，才能把携带的 B 页面计为已实际展示。

完成工具必须包含非空证据，只允许引用有效 A 页及已经展示的 B 页；允许引用先前展示后折叠的页面。最终仅将 `is_duplicate` 和 `conclusion` 映射到结果，内部 `reasoning` 与原始对话不会成为拒绝意见。

机器校验保证类型、引用与执行边界，不证明模型已充分检查或事实正确。重复判断对正文及附件的充分覆盖由系统任务规则要求，语义准确性还需人工标注实验验证。

## 多轮记忆、纠错与审计

`compare_files()` 每轮执行“检查预算 → 请求模型 → 追加私有审计 → 校验唯一真实工具 → 校验参数与页面状态 → 接受读页或完成”。普通文本、多个工具、未知工具、截断响应、无效 JSON、错误参数和未展示页证据都不能形成结果。

上下文分为独立固定前缀、工具执行所需局部页面元信息、全部已接受动作的原生思考与合法工具历史、连续失败的最小修正反馈及私有审计。失败反馈只解释位置、问题和修正方向，原始正文及完整无效参数不回显、不降级解析。纠错不追加 user，也不伪造 tool_call_id；无合法调用时，用程序生成的 assistant 最小校验提示继续纠错，该提示不当作模型原文或文件事实。连续失败共用同一纠错链，只有动作通过全部校验后才清空整段链，并重置计数。

合法读页动作通过全部校验后，其完整原生思考和 assistant/tool 回执持续保留至本次比较结束；后续翻页和友好折叠不清除思考。普通正文不作为思考回填，失败轮次的思考只留私有审计；下一次动作成功时清理纠错链，但保留已有合法历史。

兼容服务返回的 `reasoning_content` 优先，缺失或空值时使用 `reasoning`；后续 assistant 消息同时携带两个别名的同一完整文本，适配不同版本接口与模板，并传入 `preserve_thinking=true`。不拼接成普通 user/content 文本，不截断思考。当前服务的 `/tokenize` 实测发现，仅发送 `reasoning_content` 会丢失原文，加入 `reasoning` 字段并开启保留后，已验证原文进入实际 token 序列。

思考按单份文本计入上下文预算，合法历史受总轮次及上下文容量约束；不足时明确失败，不能静默清空或裁剪。它只作为模型继续比较的历史，不写入权威观察、boolean 或最终反馈。

每轮原始 SDK 响应、用量、耗时、接受状态及反馈保存在本次会话的独立审计列表；如配置 `audit_sink`，在退出时交给调用方。纠错链清除不删除审计。默认不写文件，审计也不进入主图业务状态。

每个文件对独立维护工具历史、局部页面元信息及计数，共享只读页面和模型客户端不共享会话状态。实现遵循[合同服务上下文规范](../../../../../../现象合同智能管理平台/contract-service-be/description/standard/agent-context-management.md)及[提示词规范](../../../../../../现象合同智能管理平台/contract-service-be/description/standard/prompt-engineering.md)。

## 独立配置与失败边界

`app/config/file_deduplication.py` 加载项目 `.env`，进程环境变量优先，也支持通过 `FileDeduplicationContext.settings` 显式注入。与消息接收配置及模型 HTTP 并发分别管理。

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `FILE_DEDUPLICATION_MAX_VISIBLE_PAGES` | 3 | B 同时可见页面上限。 |
| `FILE_DEDUPLICATION_MAX_ROUNDS` | 32 | 模型对话总轮数，包含失败轮次。 |
| `FILE_DEDUPLICATION_MAX_CONSECUTIVE_ERRORS` | 3 | 连续失败达到此数时中断。 |
| `FILE_DEDUPLICATION_MAX_PAGE_READS` | 24 | 成功读页动作上限，包含重开。 |
| `FILE_DEDUPLICATION_MAX_OBSERVATIONS` | 128 | 用于折叠说明的不同已接受观察条目上限。 |

每次请求还检查视觉预算和上下文容量。视觉 token 使用渲染估算，文字按 UTF-8 字节数保守估算，并预留生成、提示词与运行余量；这不是服务端 tokenizer 的精确计数，可能提前拒绝较长上下文。

模型连接或请求失败直接抛出，不在 Agent 中重复调用；底层明确媒体 cache miss 的一次重填机制保持不变。超限或不能形成有效终态抛出 `FileComparisonError`，绝不默认 false。主图沿用“有明确 true 可拒绝；无 true 且存在未知则中断”的边界。
