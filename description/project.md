# 知识沉淀注册中心后端

> **文档定位：** 本文说明项目目标、基本职责和总体业务流程。当前已实现申请接收、智能辅助审核、人工最终审核与结果反馈，具体契约和运行边界由对应专题文档维护。

---

## 项目定位

知识沉淀注册中心后端面向知识沉淀体系中的各个子平台，集中接收和审核数据入库、数据删除申请，并向子平台反馈审核结果，支持子平台据此处理数据。

本项目同时提供一系列智能体功能，辅助并赋能注册中心的管理工作。具体能力与使用场景将在后续需求中逐步明确。

已提供独立的[人员系统](capability/application/personnel.md)，通过本地人员配置、密钥登录和免登码识别人工审核人；[入库审核接口](api/ingestion-review.md)使用登录身份确定最终审核人。

---

## 基本职责与边界

- **申请接收：** 通过消息中间件服务获取各个子平台提交的数据入库、数据删除申请。
- **申请审核：** 在注册中心对申请进行审核，审核结果为通过或拒绝。
- **结果反馈：** 将审核结果反馈给对应子平台，由子平台根据反馈执行相关数据处理。
- **智能体能力：** 为注册中心管理工作提供智能体支持，具体功能及其与审核流程的关系后续定义。

注册中心负责申请的接收、审核与结果反馈；子平台负责发起申请，并根据反馈处理自身数据。

---

## 核心术语

| 术语 | 含义 |
| --- | --- |
| 子平台 | 知识沉淀体系中发起数据申请、接收反馈并处理数据的平台。 |
| 注册中心 | 集中接收申请、开展审核并反馈结果的平台。 |
| 数据申请 | 子平台提交的数据入库申请或数据删除申请。 |
| 审核结果 | 注册中心对申请作出的通过或拒绝结论。 |

---

## 总体业务流程

1. 子平台发起数据入库或数据删除申请。
2. 注册中心后端通过消息中间件服务接收申请。
3. 在注册中心对申请进行审核，作出通过或拒绝的结论。
4. 注册中心向对应子平台反馈审核结果。
5. 子平台根据反馈处理相关数据。

智能体功能用于支持注册中心管理工作，其具体工作流及接入位置随功能设计逐步补充。

## 后续完善方向

后续将按真实业务数据完善智能体效果评估、容量与性能验证及运维能力；当前已实现范围和限制以各专题文档及接口契约为准。

接口契约、数据定义、工作流和运行配置等细节应在对应专题文档中维护，并通过统一导航提供入口。

本项目使用 MySQL 作为关系型数据库，镜像与统一部署由同级的 `registry-deploy` 项目维护，MySQL 镜像目录为 `registry-deploy/mysql`；资源表由 `registry-deploy/mysql/init/` 脚本在 MySQL 容器首次初始化时创建，后端已提供入库申请持久化能力。

已接入 `middleware-service` 的平台注册登录与心跳服务，后端启动后自动建立并维护平台会话。后台入库接收服务持续执行完整入库图，下载前按[源文件身份规则](capability/application/source-identity.md)阻断同平台同源的活跃重复申请；重复申请自动反馈拒绝结果，不重复申请保存原文件、摘要向量与通行证建议到 SQLite 待审队列后确认消费。[人工入库审核](capability/application/ingestion-review.md)已实现待审列表、原件读取、批准后的正式存储及拒绝反馈。已提供[删除申请接收服务](capability/application/deletion-consumer.md)，以正式资源原文件作为审核引用，保存待审记录或发布自动拒绝后确认消费。[人工删除审核](capability/application/deletion-review.md)已实现待审列表、按审核员查询历史和最终决定；批准后移除正式资源并保留原件，完成本地存储后向中间件反馈。

已增加[平台目录刷新服务](capability/application/platform-directory.md)，启动后定期从中间件读取全部平台与登录会话存活状态，保存在带更新时间及过期标记的内存快照中。

已提供 [MyVector 与 vLLM 向量检索](capability/infrastructure/myvector.md)，并从正式资源表筛选同平台正式文件，建立可重建的 HNSW 索引缓存。

[入库申请工作流](architecture/workflow/ingestion/readme.md)已实现内存下载、摘要向量化、候选匹配、并行比较调度及拒绝反馈。节点 C 已接入[文件判重子图](architecture/workflow/file-deduplication/readme.md)，已实现多轮工具调用、友好页面折叠及严格 boolean、最终结论输出；[通行证推荐子图](architecture/workflow/passport-recommendation/readme.md)已建立三个节点及输入输出契约，并实现复用已有 HNSW 封装的跨平台搜索与通行证聚合；原文件、摘要向量和完整推荐列表的 SQLite 待审核暂存已实现；通行证推荐已实现共享当前 PDF 的组级并发模型判断和严格 JSON 验收，推荐效果仍需真实样本评估，文件判重已完成小样本真实模型验证，总体准确率仍需扩大样本评估，完整图已接入 FastAPI 后台消费者，持续消费、失败重试与依赖生命周期见[入库申请接收服务](capability/application/ingestion-consumer.md)。

## 文档入口

SQLite 审核存储基础设施已准备，位置为 `data/review-log/registry.db`，提供入库审核和删除审核两张表；入库接收与拒绝分支已接入审核写入，入库待审核数据完整暂存在 SQLite，审核通过后才进入 MySQL 正式资源表并保存入库备注；正式资源不保存审核状态或推荐列表；字段与状态见[审核表契约](architecture/data/review.md)，运行方式见 [SQLite 基础设施](capability/infrastructure/sqlite.md)。
