# 多轮 Agent 上下文与记忆管理规范

> **适用范围：** 新增或修改具有多轮模型交互、函数工具、工作区或错误恢复的 Agent。模型消息、权威状态与私有审计必须分别维护，动作通过全部校验后清除整段连续失败轨迹。

---

## 1. 上下文分层

| 层级 | 保存内容 | 生命周期与可见性 |
| --- | --- | --- |
| 固定前缀 | 任务规则、固定输入、稳定工具布局。 | 同一任务保持稳定，按需给模型。 |
| 权威工作区或局部状态 | 已接受事实、页面可见状态、合法引用与必要计数。 | 程序维护，只按节点契约暴露必要内容。 |
| 合法短期历史 | 通过校验的动作及工具结果。 | 在任务预算内保留或按节点契约折叠。 |
| 临时纠错历史 | 连续失败期间的最小修正信息及必要失败调用。 | 只供连续纠错，下一次动作完全接受后整体清除。 |
| 私有审计 | 原始响应、工具参数、接受状态、用量、耗时和错误。 | 不给模型，不因纠错清理而删除。 |
| 下游结果 | 通过全部校验的正式结构化结果。 | 仅提交成功结果，不接收普通文本或半成品。 |

模型消息不是权威事实库，私有审计也不能直接拼回模型历史。提示词的信息边界遵循[提示词工程规范](prompt-engineering.md)。

---

## 2. 单轮接受流程

每轮先追加私有审计，再校验协议、工具名称、参数 Schema、当前状态、业务约束和上下文预算。任一步失败都不能提前修改权威状态或下游结果。

```text
接收响应 → 私有审计 → 协议校验 → 参数校验 → 状态与业务校验
  失败：保留原权威状态，追加最小反馈，有限重试或显式失败
  成功：清除整段失败链，接受当前动作，提交合法状态或终态
```

读页、观察和窗口调整等操作应先形成候选状态；全部校验通过后再一次接受，避免失败读页消耗正式额度、污染观察或改变已接受页面历史。

---

## 3. 连续纠错的生命周期

第一次失败时建立纠错边界，或使用独立列表保存该连续失败段。零工具、多工具、未知工具、非法 JSON、Schema 错误、非法页码和业务错误共用该段，不能每轮只清最后一条反馈。

反馈只说明位置、问题和修正方向，不回显完整错误输出、异常堆栈或敏感参数。无法取得真实工具调用时不能伪造调用标识、执行成功或文件事实；具体反馈角色及形式由节点协议规定。

恰好一个工具调用只表示格式恢复。只有当前动作同时通过协议、参数、状态、业务及预算校验后，才能整体删除此前失败调用、失败反馈和失败尝试，重置连续错误计数，并把正确动作写入合法历史或正式状态。私有审计继续保留全部失败轮次和成功事实。

轮次、连续错误、读页和上下文容量均须有明确上限。超过上限时显式失败，不用空对象、普通文本或默认布尔值冒充结论；最后一次反馈若未实际发起下一轮请求，不能声称模型已收到并修正。

---

## 4. 合法历史、页面与工作区

工作区只保存继续任务所需且经过验证的信息，不保存原始失败调用、完整无效参数或推理草稿。检查点或终态仅在自身全部条件通过后提交，重建上下文时给出足够的下一步方向。

页面是否已加载到内存、是否放入请求、是否已实际发送并收到响应，是不同状态。证据引用只能按节点契约使用已展示资料；折叠卡片不是原图或充分阅读证明，需要细节时重新打开。

若节点允许保存合法动作的原生思考，其仅用于继续当前会话，不成为权威观察、用户反馈或业务结论。保留、折叠和预算策略必须在节点文档明确，不能在预算不足时静默截断并继续宣称证据充分。

---

## 5. 并发与审计隔离

每个最小任务独立维护消息、连续纠错段、恢复计数、页码状态和审计。可共享不可变 PDF 页面和受并发限制的客户端，不能共享可变消息历史或将另一分支的失败带入当前分支。

私有审计默认不进入模型或下游业务状态。需要落盘时按[实验规范](experiment.md)使用独立目录，避免记录认证凭据；清理模型上下文不得删除审计原始记录。

---

## 6. 本项目接入与验证

[文件判重](../architecture/workflow/file-deduplication/context.md)采用固定前缀、合法工具历史、局部页面状态、独立纠错列表及会话审计；没有通用工作区对象。动作成功后清理纠错段，合法原生思考继续保留，页面按窗口折叠。以其专题文档和实现为准，不强制为满足分层形式新增工作区。

[通行证推荐](../architecture/workflow/passport-recommendation/readme.md)采用组级单次 JSON 判断，不构造多轮工具历史；仍须在响应通过结构和引用校验后才发布结果，并保持各组隔离。后续改为多轮交互时须执行完整纠错生命周期。

新增或修改多轮节点至少验证：合法动作、不同类型连续失败、格式恢复但参数仍错、成功后整段失败轨迹消失、合法状态保留、私有审计完整、并发无泄漏，以及达到上限后不发布半成品。测试必须显式使用 `tests/tmp/` 等隔离目录，不写真实 `data/`。
