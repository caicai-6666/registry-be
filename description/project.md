# 知识沉淀注册中心后端

> **文档定位：** 说明项目目标、职责和全局边界。接口、字段、工作流和运行配置由对应专题文档维护，统一入口见[项目文档导航](readme.md)。

---

## 项目定位

注册中心后端面向知识沉淀体系的各个子平台，集中接收数据入库和删除申请，结合智能辅助审核与人工最终审核管理正式文件，并向来源平台反馈结果。

本项目提供申请接收、摘要向量检索、智能判重、通行证推荐、待审管理、正式文件读取和等级维护。智能结果用于辅助审核或按既定规则自动拒绝，不替代人工批准。

用户在同级 `knowledge-accumulation-be` 登录；注册中心前端位于 `registry-fe`，MySQL 镜像和统一部署由 `knowledge-accumulation-deploy` 管理。

## 基本职责与边界

| 领域 | registry 职责 | 外部职责 |
| --- | --- | --- |
| 申请与结果 | 从中间件消费申请，保存审核记录，反馈通过或拒绝。 | 子平台发起申请并消费结果，处理自身数据；中间件负责消息交付。 |
| 智能辅助 | 摘要向量召回、同平台文件判重、跨平台通行证推荐。 | 模型服务提供嵌入和多模态推理；效果需真实样本验证。 |
| 正式存储 | 人工批准后写入正式资源；删除批准后移除资源并保留原件和审核快照。 | MySQL/MyVector 的镜像与首次建表由统一部署提供。 |
| 人员与权限 | 查询共享人员目录；手动刷新姓名、全部一级部门及任职资料；增量维护文件权限和平台管理员。 | 知识后端负责首次员工初始化、登录、头像存储及用户/管理员全表注册。 |
| 文件授权 | 管理入口验证 registry 管理权；独立用户和可信后台入口按实时文件等级授权。 | 中间件提供中央用户查询、平台身份校验和管理员名单。 |

注册中心不签发用户登录 token，不建立本地登录缓存，不维护与知识后端分叉的人员或权限副本。中央全表发布与 registry 增量变更仍需跨后端写入协调，进程内锁不能保证跨系统一致性。

## 核心术语

| 术语 | 含义 |
| --- | --- |
| 子平台 | 发起数据申请、接收反馈并处理数据的平台。 |
| 数据申请 | 子平台提交的数据入库申请或删除申请。 |
| 正式资源 | 已通过人工入库审核、写入 MySQL 并保存正式原件的文件。 |
| 待审记录 | SQLite 中保存的申请、推荐或文件引用，尚未形成最终处理结果。 |
| 文件等级 | 与员工在文件来源平台的权限等级比较的下载条件，与管理员资格独立。 |

## 总体业务流程

**入库：** 消费申请 → 按同平台同源身份拦截活跃重复申请 → 下载原件并生成摘要向量 → 同平台相似文件比较 → 跨平台通行证推荐 → SQLite 暂存待审申请及原件 → 确认消费。确认重复时自动保存拒绝记录并反馈；人工批准后才写入 MySQL 和正式目录，人工拒绝不创建正式资源。

**删除：** 消费申请 → 按来源平台与 `source_id` 定位正式资源 → 校验完整通行证集合 → 保存待审记录并确认消费。目标不存在或通行证不符时自动拒绝；人工批准后移除正式资源、保留原件及信息快照，再反馈来源平台。

两类最终审核均在本地处理完成后发布结果。MySQL、SQLite、文件系统与中间件之间没有统一事务，未完成处理保留恢复状态；发布成功不等于来源平台已经完成消费。

流程契约见[入库工作流](architecture/workflow/ingestion/readme.md)、[人工入库审核](capability/application/ingestion-review.md)及[人工删除审核](capability/application/deletion-review.md)。

## 身份与文件读取

管理接口统一校验中央用户登录和当前注册中心管理员身份，人工审核以可信 userid 记录审核员。普通用户通过[文件权限下载](api/resource.md#按用户权限获取正式文件原件)，使用用户 token 并比较来源平台的实时员工权限与文件等级。

知识后端助理和定时任务通过[可信后台原件接口](api/resource.md#可信后台代用户获取正式文件原件)，使用经中间件验证的 `knowledge-accumulation` 平台 token，以及可信任务绑定的员工 userid；不要求用户登录，仍按同一实时文件权限规则授权。未知文件等级、缺少来源平台授权或等级不足均拒绝读取，管理员身份不用于这两个入口旁路。

头像由知识后端保存，registry 仅提供管理员专用 HTTP 代理。完整身份与故障边界见[授权依赖](capability/application/authorization.md)。

## 存储与运行边界

正式资源写入 MySQL `resources`；入库和删除的待审、历史、恢复凭据及辅助审计保存在 SQLite，默认位置为 `data/review-log/registry.db`。待审附件、正式原件及删除保留原件分别由受控目录管理，详见[审核文件存储](capability/infrastructure/review-file-storage.md)。

部署采用单实例、单 worker，MySQL 与后端数据使用独立命名卷。新空卷初始化已包含员工任职资料和多部门字段；已有卷不会因重建镜像自动升级。SQLite 由后端初始化和升级，MySQL 结构由部署或显式迁移维护。入口、前缀、配置覆盖和数据迁移见[运行配置](capability/application/runtime.md)。

## 当前限制与完善方向

- 智能判重与通行证推荐以 PDF 页面为主要证据；支持下载其他格式不等于支持其智能审核。
- HNSW 属于近似检索，候选数量和阈值影响召回；推荐质量与判重总体准确率仍需扩大真实样本评估。
- 平台目录使用带过期标记的内存快照；HTTP 健康检查只确认 Web 入口，不能证明数据库、中间件、模型或业务表就绪。
- 后续按真实业务完善效果、容量、性能及运维验证，不将小样本实验结果视为总体质量保证。
